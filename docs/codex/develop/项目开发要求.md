# 项目：本地 AI 图片编辑 Web

你是一名资深全栈工程师和计算机视觉工程师。请在当前代码仓库中开发一个可实际使用的本地图片编辑 Web 应用，重点实现高质量 AI 抠图、蒙版编辑、颜色替换以及支持多分支的历史版本管理。

## 一、开发原则

1. 先检查当前仓库的目录结构、依赖、现有代码和运行方式。若已有成熟技术栈，优先复用，不要无故重写。
2. 若仓库为空，默认采用 Vue 3 + TypeScript + Vite + Pinia 前端，以及 Python + FastAPI + PyTorch + Pillow + NumPy + OpenCV 后端。画布渲染可以采用原生 Canvas 或合适的 Canvas 封装库。
3. 这是优先面向桌面浏览器的单用户本地应用，界面中文化。所有图片编辑和 AI 推理均在本机进行，不得将用户图片发送到第三方服务。
4. 保持清晰的模块边界：画布渲染、选区管理、像素处理、模型推理、历史版本、持久化和导出应分别实现，不要堆积在一个组件中。
5. 不允许只实现静态 UI、模拟进度或伪造 AI 推理结果。每个完成的按钮都必须具有真实功能。模型不可用时，应明确提示原因，而不是返回伪造蒙版。
6. 不要一次性堆砌所有功能。按照本文的开发阶段逐步实现，每个阶段都要运行必要的测试并修复问题。无需等待我确认，直接持续完成可实现的阶段；遇到模型授权、下载或外部依赖阻塞时，先完成其他功能，并提供清楚的配置说明。
7. 你的环境必须在当前项目下创建，不要使用全局 Python 虚拟环境。模型也必须安装在项目目录下。要求结构清晰，不要都塞在一级目录下。
8. 你可以参考其余的github项目来学习效果好的方法。

## 二、整体界面布局

使用左、中、右三栏布局：

- 顶部常用工具栏：打开图片、保存项目、撤销、重做、查看原图、适应窗口、100% 缩放、缩放比例、导出图片。
- 左侧工具栏：自动抠图、自动对象选择、点选或框选、圆形画笔、方形画笔、矩形选区、椭圆选区、颜色选择、选区增减等工具。
- 中央画布：优先占据可用空间，显示图片、透明棋盘格、选区蒙版和操作预览。支持图片居中、适应窗口以及真实像素比例查看。
- 右侧属性面板：随当前工具显示相应参数，包括笔刷尺寸、颜色容差、连续选择、羽化、边缘调整、替换颜色、渐变参数和历史版本树。

左右侧栏应可折叠。面板调整不得导致图片尺寸或图像像素被改变。

## 三、画布交互

1. 支持拖放图片、文件选择和粘贴图片。第一版支持 PNG、JPEG、WebP。
2. 使用鼠标滚轮缩放图片，缩放中心应锚定鼠标指针所在的图像位置，不能出现鼠标指向图片某点但缩放后该点跳走的情况。
3. 支持空格加鼠标拖动平移画布，适当支持中键拖动。
4. 支持适应窗口、100% 实际像素、放大、缩小和居中。
5. 所有笔刷、点选、框选坐标都必须正确映射到原图像素坐标。改变缩放比例或画布布局后，不得出现选区位置偏移。
6. 增加一个明确的“查看原图 / 查看编辑结果”切换按钮。点击后临时显示未经修改的原图，再点击恢复当前编辑结果。比较操作不得改变当前编辑状态，不得创建历史节点。
7. 选区可使用半透明彩色覆盖层显示，并支持透明棋盘格作为背景。

## 四、选区系统

建立统一的全分辨率灰度蒙版作为选区数据结构。约定 0 表示未选中，255 表示完全选中，中间值表示软边缘或部分选中。所有选择工具必须输出相同规格的蒙版。

### 4.1 自动选择

实现以下功能：

- 自动移除背景：生成前景蒙版，可反转为背景选区。
- 语义对象选择：用户输入对象描述，例如 person、sky、cat、car，自动分割与描述匹配的区域。
- 如果可行，提供点击目标或框选目标进行交互式分割的入口。
- AI 推理得到的蒙版应允许用户继续用画笔或其他选择工具修改。

模型优先考虑：

1. 默认抠图模型：Hugging Face 上的 ZhengPeng7/BiRefNet。
2. 按文本进行概念分割：评估 facebook/sam3；由于其模型权重需要申请访问，且使用独立许可，必须检查授权、依赖和本地加载方式。若当前环境无法获取权重，不得假装加载成功。
3. 点击和框选分割的可替代方案：评估 facebook/sam2.1-hiera-large，以及必要时使用 IDEA-Research/grounding-dino-base 进行文字目标检测，再将检测结果用于分割。

模型使用适配器接口组织，避免业务组件直接依赖具体模型。模型 ID、缓存目录、推理设备和运行参数应可配置。必须检查模型许可、权重访问条件和自定义代码依赖，记录在 README 中。

启动后应检查 CUDA 是否可用，优先使用 NVIDIA GPU，并支持 CPU 回退。模型在应用运行期间应尽量复用已加载实例。提供模型加载状态、推理进度、错误信息和可理解的安装或授权提示。

自动背景分割、文本对象分割和用户手动选择是不同能力，不得将它们混为同一种算法。

### 4.2 手动选择

至少实现：

- 圆形画笔：用于涂抹选择和擦除选区。
- 方形画笔：用于涂抹选择和擦除选区。
- 矩形选区。
- 椭圆选区。
- 颜色选择工具，类似魔棒。
- 选区反选、全选、清空选区。
- 选区增加、选区减去；如实现交集，也要提供对应入口。

画笔支持调整直径，拖动时应形成连续笔迹，而不是只在鼠标采样点上绘制离散圆点。笔刷尺寸以原图像素定义，并在不同画布缩放比例下正确映射。

颜色选择工具需要支持：

- 从图片上选取参考颜色。
- 调整颜色容差。
- 连续区域模式：只选择与参考颜色相近且与采样点连通的区域。
- 非连续区域模式：选择全图中与参考颜色足够接近的像素。
- 使用合理的颜色距离度量，并对抗锯齿边缘提供可调容差。

### 4.3 蒙版编辑

实现选区边缘羽化、选区膨胀和收缩，以及适当的边缘平滑。修改蒙版不能直接破坏原始图片。

自动选区与手动选区应能组合使用。例如先自动选中人物，再用画笔减去头发旁的一块背景。请对蒙版组合规则编写单元测试。

## 五、选区颜色替换与填充

用户可针对当前选区执行以下操作：

1. 透明化：清除选中区域的有效透明度，支持 PNG 导出。
2. 纯色替换：将选区替换为用户指定的 RGB 或 HEX 颜色。
3. 渐变替换：至少支持线性渐变，可配置起始颜色、结束颜色、渐变方向和范围；条件允许时增加径向渐变。
4. 邻域渐变填充：从未选中区域的边界附近采样颜色，估计局部颜色变化并生成平滑的渐变延展。界面须说明这是邻域颜色估算，不等同于完整的语义内容修复。

技术要求：

- 所有操作遵循蒙版的软边缘权重，羽化边界不能出现明显锯齿或生硬接缝。
- 透明化操作应正确计算新的 Alpha 通道，并保留未选中区域的像素与原始透明度。
- 纯色和渐变替换应合理处理部分选中像素，不能把软蒙版简单阈值化为黑白。
- 不得因为视口缩放而降低导出图片的实际分辨率。
- 暂时不要求实现复杂的物体移除、生成式填充或图层系统；应预留扩展接口。

## 六、多分支历史版本系统

这是项目的核心要求，不能只实现普通的 Ctrl+Z / Ctrl+Y 栈。

采用有根历史树或有向无环图管理编辑版本，至少支持以下流程：

1. 原图 A 执行修改后得到 B，再修改得到 C。
2. 用户从 C 连续撤销回 A。
3. 用户从 A 执行新修改得到 D，再得到 E。
4. 此时 C 仍然存在且可以被重新访问，不得因为创建 D、E 而删除 C。
5. 支持查看历史分支并选择历史节点恢复对应版本。

每个已确认的修改应生成独立历史节点。节点至少记录：

- 唯一 ID。
- 父节点 ID 和子节点 ID 列表。
- 操作类型、参数和时间。
- 对应的结果图像快照或可可靠恢复的状态。
- 可用于历史面板的缩略图。

原图是不可修改的根节点。当前节点只是历史树中的一个活动指针。撤销是移动当前指针，创建新编辑时是在当前节点下创建新分支。重做应允许选择多个子节点，而不只是无条件前进到唯一的下一节点。

只将已确认的图像修改写入正式历史。鼠标移动、临时预览和查看原图等不应反复生成节点。

历史树及项目内容必须在页面刷新或应用重新启动后仍能恢复。优先使用 IndexedDB 持久化原图、图像快照、缩略图和历史元数据。请使用合适的 Blob 存储方式，避免将大图像转成 Base64 后反复复制到内存中。必须处理浏览器存储空间不足、快照写入失败和项目恢复失败的情况，不能静默丢弃历史版本。

提供适当的历史面板（可以设计在回退/重做这两个工具的中间），可以识别分支、节点和当前版本。历史数据结构与界面组件应分离。

## 七、项目保存和图片导出

明确区分两种操作：

- 保存项目：保留原图、编辑结果、历史分支及恢复所需的数据。
- 导出图片：生成用户最终需要的图片文件。

导出至少支持 PNG、JPEG 和 WebP。PNG 保留透明通道；JPEG 不支持透明度，需要允许用户指定透明区域的铺底颜色。导出图片应保留原始图像的宽、高，不得导出画布截图或低分辨率预览。

项目保存应有明确成功或失败提示。不得将“导出图片”等同于“保存全部历史项目”。

## 八、工程架构和性能

前端至少划分以下模块：

- AppLayout 和工具栏。
- ImageViewport / CanvasRenderer。
- SelectionManager。
- MaskRenderer。
- EditOperations。
- HistoryManager。
- ProjectStorage。
- ExportService。
- API Client。

后端至少划分以下模块：

- API 路由和请求模型。
- 模型管理器与模型适配器。
- 自动抠图和对象分割服务。
- 蒙版后处理服务。
- 图像处理服务。
- 模型状态、日志和错误管理。

API 推理不能长时间阻塞请求处理。需要显示执行状态，正确处理超时、错误和任务取消。图像处理必须考虑高分辨率图片的内存占用，尽量避免不必要的完整图像复制；模型推理可以使用合适的缩放策略，但最终蒙版必须映射回原图分辨率。

原图、蒙版、显示预览和最终导出是不同的数据。始终保留原始像素数据，不能把低分辨率显示结果当作原图保存。

## 九、开发阶段

### 阶段一：建立可运行的基础编辑器

完成应用骨架、三栏布局、图片导入、画布平移和滚轮缩放、原图对比切换、画笔及几何选区、透明化与纯色替换、图片导出。

同时建立统一蒙版和图像坐标系统。

### 阶段二：AI 分割

实现真实的 BiRefNet 推理和前景/背景蒙版生成。然后集成 SAM 3 或符合许可条件的分割替代方案，实现按对象类别自动分割，并提供模型不可用时的明确提示。

### 阶段三：复杂填充和蒙版优化

实现颜色容差选择、连续与非连续选择、羽化、边缘调整、渐变替换和邻域渐变填充。

### 阶段四：持久化与多分支历史

实现历史树、分支导航、快照存储、项目恢复和多分支测试。确保上述 A→B→C、回到 A 后创建 A→D→E 的流程能够完整通过。

### 阶段五：质量检查

完善错误处理、性能测试、README、安装说明、模型许可说明和启动脚本。修复实际运行过程中发现的问题。

每个阶段结束时都应保持应用可启动、功能可验证。若某些功能受环境或模型授权限制，明确报告具体阻塞原因以及完成度，不要用伪实现冒充完成。

## 十、验收标准

至少验证以下情况：

1. 导入一张横版高分辨率 PNG 后，画布能正常适应窗口；滚轮缩放和平移不会改变原始分辨率。
2. 在不同缩放比例下画笔、矩形、椭圆的选区位置准确。
3. 自动抠图生成实际蒙版，并可继续手动编辑；选区可以正确反选为背景。
4. 连续与非连续颜色选择表现不同，且容差可调整。
5. 蒙版边缘可以羽化；透明化后 PNG 具有正确的 Alpha 通道。
6. 纯色和渐变替换遵循蒙版权重，未选中区域不被意外修改。
7. 切换原图预览不会丢失编辑状态。
8. 历史树能保留多个分支；从 A 创建 D、E 后仍可重新访问 C。
9. 刷新页面或重启应用后，保存的项目能够恢复。
10. PNG、JPEG、WebP 导出结果尺寸正确；PNG 透明区域正确。
11. 模型下载、加载和推理失败时显示清晰错误，不会静默返回错误图像。

请为关键逻辑编写测试，至少包括画布坐标映射、蒙版组合、透明度计算、历史树分支及项目持久化。
